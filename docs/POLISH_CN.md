# 阶段 2 完善

[English](POLISH.md) | [中文](POLISH_CN.md)

本文件记录一个批次的开发过程：对已实现功能所做的可靠性与可用性工作。

## 核心修复

- **冻结与写入冲突。** 对已冻结记录执行显式写入（`Write selected`）时，先重新解析该记录——因为指针自上次冻结节拍起可能已经移动——当解析出的范围与另一个已启用的冻结重叠时，以 `CE_INVALID_ARGUMENT` 拒绝这次写入。不会写入目标，保存的冻结字节也不变；冲突会关闭该记录的冻结。冻结节拍套用同一条冲突规则：后台冻结一旦开始重叠，就丢弃自己的冻结，而不是写入。对未冻结记录的显式写入保持原有行为。
- **V1 CT 保存预检。** V1 保存在触碰目标位置之前会校验整个集合：只要有任何记录是 V1 子集无法表达的——非 V1 类型、重复地址——保存就失败，返回 `CE_UNSUPPORTED` 并指向 V2 导出。目标位置上已有的文件原样保留；集合绝不合并、绝不裁剪，无法重新加载回来的表绝不写出。同地址多记录是 V2 支持的形态。

## 真实扫描状态

`CE_GetScanStatusV2` 与它自带的 80 字节 `CeScanStatusV2` 是新增的：现有结构与版本值不变。快照携带操作 ID、阶段、活动标志与取消请求标志、`has_scan`/`can_undo`、代际，以及进度单位及其计数。

- 首次扫描的枚举阶段没有已知总量；之后的进度以可读字节计数（不可读的页不计入）。下次扫描统计的是上一代际的候选。
- 读取源文件不等于提交文件：`writing` 与 `committing` 分别显示，只有 `COMPLETED` 才表示成功。取消不会被伪装成 100%：取消落在最终提交时，计数可能已经等于总量，而终态仍是 `CANCELLED`。
- 查询只短暂尝试加锁（try-lock），可能不等扫描结束就返回 `CE_BUSY`；调用方重试，并保留上一次快照。
- 只有当核心确实持有上一代际时，Undo 才可用：首次扫描时从不可用；Undo 之后（上一代际已被消费）或 New 之后也不可用。零结果的代际仍然算作历史。失败或取消的一轮会保留已提交结果与撤销状态。

## 记录刷新

地址列表新增了一列 `Current value`。它在预算约束下分批轮询当前页的各行——仅在窗口可见且未最小化时进行，每 500 ms 轮询一次，每次轮询 16 行 / 64 KiB、最多 12 ms 的工作量，值预览到前 256 字节。长值带有明确的截断提示；不可读的行报告错误，而不是 0。

隐藏窗口只会暂停这些实时读取；它从不暂停用户启用的冻结。写入失败或后台冻结失败会关闭该行的 `Frozen`，并把错误留在 `Last core status`；之后的状态查询不会替换这条诊断信息。

## 内存页

- `Resolve` 从表单重新解析地址/指针链。
- `Previous 256` / `Next 256` 在已解析的页地址上移动，不修改解析输入。
- 会使宿主地址范围上溢或下溢的翻页会被拒绝；完整的 256 字节窗口必须落在范围内。
- 不可读的格子会被标记（`??`），且不可编辑。

## 证据与边界

`polish_core_tests` 是新的测试套件；`core_tests`、`typed_tests`、`hotkey_tests`、`runtime_tests` 与 `runtime_v2_tests` 继续作为回归运行。已退役 UI 的源码、绑定测试与探针冷存于 `baseline/pre-webui/`——纯存档，不是回滚路径，构建不引用。参考实现的源码不变。
