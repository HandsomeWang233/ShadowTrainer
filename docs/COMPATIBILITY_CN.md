# 兼容性与运行时规范

[English](COMPATIBILITY.md) | [中文](COMPATIBILITY_CN.md)

本文说明外部调用方可以依赖什么，以及每个入口点会拒绝什么。ABI 定义于 `include/ce/api.h`（第 1 版）与 `include/ce/api_v2.h`（第 2 版）；以下规则都是代码与测试实际遵守的。

## DLL、加载与热键

只有一个 x64 的 `shadowtrainer.dll`。它只导入 Windows 系统库——WebView2 加载器是静态链接的，因为并列放置（side-by-side，**指 DLL 需与宿主可执行文件同目录并存的那种加载方式**）的 `WebView2Loader.dll` 在别人的进程里靠不住。

- 可以用任何常规机制加载：`LoadLibraryW`、调试器、注入器。
- 加载引用归调用方所有，且必须一直持有到 `CE_RequestStop` + `CE_WaitStopped` 成功为止。停止会卸载该模块，所以之后要再开一次会话，就得重新加载。
- 隐藏窗口绝不会停止扫描或冻结。

**热键。** 反引号（`VK_OEM_3`），每 16 ms 从该键的高位采样一次，在按下沿（press edge，**按键由松开转为按下的那一刻**）触发。它只在当前前台窗口属于宿主进程、且没有模态对话框弹出时才生效；启动之后、或失去生效资格之后，必须先观察到一次合规的释放，随后的按下才会触发。窗口隐藏期间采样仍在继续。

这里没有键盘钩子：宿主的输入既不会被拦截，也不会被独占抓取，采样器本身也不会主动抢前台。采样带来两个后果：极短的轻击可能正好落在两次采样之间，而该键打出来的字符取决于键盘布局。

## API 版本

- V1（`include/ce/api.h`，`CE_GetApiVersion == 1`）保持其结构体、导出符号与版本号不变。
- V2（`include/ce/api_v2.h`，`CE_GetApiVersionV2 == 2`）是追加式的。它引入了显式的结构体版本号、调用方提供的缓冲区，以及扩展类型。
- V1 的结果读取或下次扫描调用只接受类型兼容的 32 位有符号会话；持有其他类型数据的会话会被以 `CE_UNSUPPORTED` 拒绝，而不是被截断。
- V2 的请求会先校验 `size`/`version`，再做其他任何事。输出写入调用方提供的缓冲区，所需容量由 `required` 报出。
- V2 的结果/指针结果读取会携带一个代际（generation，**用于判断读到的数据是否已被新的提交取代**），不匹配就返回 `CE_BUSY`，因此分页读取永远不会跨越一次提交。
- 进程只读视图用的是另一套「填充数组」约定；见[进程视图](#进程视图只读)。

## 类型与比较

### 值类型

| `CeValueTypeV2` | 宽度 | 说明 |
|---|---|---|
| `CE_TYPE_U8` / `U16` / `U32` / `U64` | 1 / 2 / 4 / 8 | 小端序；有无符号由 `CE_VALUE_SIGNED` 决定，十进制或定宽十六进制由 `CE_VALUE_HEX` 决定 |
| `CE_TYPE_FLOAT` / `CE_TYPE_DOUBLE` | 4 / 8 | 按下文所述解析并舍入 |
| `CE_TYPE_UTF8` | 显式 | 原始 UTF-8 字节；输入的空格会被保留 |
| `CE_TYPE_UTF16` | 显式，偶数 | UTF-16LE 码元 |
| `CE_TYPE_AOB` | 显式 | 十六进制字节对，扫描模式中支持 `??`/`A?` 通配符 |

`uint64` 绝不经过 `double`。Float/Double 文本使用固定的 C 数字区域设置解析；宿主的区域设置不会被修改。

### 比较语义

- 数值的等于/大于/小于/介于按数值比较，介于包含两端边界。
- NaN 不匹配任何数值比较；正零与负零属于完全相等。
- 已变化/未变化比较的是原始字节，所以一个未变动的 NaN 位模式仍然算未变化，而 ±0 的翻转则算作变化。
- 无穷大是合法的等于操作数。增量必须为有限值，整数增量会做溢出检查。
- 分组扫描（grouped scan）以及 Lua/Auto Assembler 自定义扫描类型仍未实现。

### 文本与 AOB

- UTF-8/UTF-16LE 的搜索值不带隐式 NUL，输入的空格会被保留。
- AOB 模式支持整字节与半字节通配符；写入和冻结不支持。
- 文本与 AOB 只支持等于，以及下次扫描时的已变化/未变化，且宽度必须保持不变。
- 单个值最大为 65536 字节；超过即为显式错误。

### 范围、对齐与 first/next 模式

- 首次扫描的范围是 `[begin, end)`；`begin == end == 0` 表示扫描宿主中已提交的可读区域。给一个非零范围，就能做确定性测试和小范围定点扫描。
- 对齐是 1 到 65536 之间的 2 的幂（UI 提供 1/2/4/8），而且是绝对的：不符合该对齐的变量永远不会匹配。32 位栈上的 `uint64` 未必按 8 字节对齐。
- 在下次扫描中，`alignment == 0` 与 `byte_length == 0` 表示沿用会话；类型、标志、宽度或对齐的任何其他改动都会被拒绝——那需要重新做一次首次扫描。
- 可以把首次扫描请求的副本传给下次扫描以保留其 `begin`/`end`，但这两个字段并不会重新定义已提交的候选集。
- 未知数值的首次扫描会把地址与历史原始值流式写入文件。

## 浮点舍入

`CeScanRequestV2.rounding` 提供参考实现的那三种精确浮点舍入，外加本实现自有的 Exact：

| 值 | 名称 | CE 对应项 | 含义 |
|---|---|---|---|
| 0 | `CE_ROUND_EXACT` | 无 | 默认：按位完全相等的数值比较。这是既有行为，传入 0 的旧请求仍然走这条路。 |
| 1 | `CE_ROUND_ROUNDED` | `rtRounded` (0) | `RoundTo(mem, -N) == entered`，即在 N 位小数上就近舍入到偶数 |
| 2 | `CE_ROUND_EXTREME` | `rtExtremerounded` (1) | 区间 `entered ± 10^-N`。**CE 在这里自相矛盾**：单精度形式用闭区间，双精度形式用开区间，本实现照抄了这一点。 |
| 3 | `CE_ROUND_TRUNCATED` | `rtTruncated` (2) | `entered <= mem < entered + 10^-N` |

枚举值刻意比 CE 的 `TRoundingType` 各高 1，因为 0 必须继续表示本实现既有的精确行为。结构体大小与偏移不变，`size`/`version` 的校验方式也不变。

### N 从哪里来

N 是调用方在小数点之后键入的位数。含有 `E`/`e` 的字面量一律得 0（CE 的 floataccuracy 规则），inf/nan 也是。N 上限为 19，超过即为错误。

### 精度下限

这些是浮点本身的限制，而不是实现上的取舍：

- 在区间模式下，当 `entered ± 10^-N` 在 `double` 中已无法区分（量级很大且精度很高）时，区间会退化为精确比较。
- 当 `|value| × 10^N >= 2^63` 时，`Rounded` 无法匹配。

### 适用范围

舍入只作用于 Float/Double 上的 `CE_CMP_EXACT`。整数、文本、AOB、介于、已变化/未变化、已增大/已减小以及增量比较完全忽略它，并且把非零舍入与任何其他类型或比较方式搭配都会被拒绝。舍入不属于下次扫描的不可变集合，因此可以在扫描之间切换。

实现绝不改动 FPU 的舍入模式（宿主自己可能会改）；就近舍入到偶数是在代码里显式完成的。

## 扫描生命周期与结果

### 提交与取消

每一次成功的扫描都会把数据、类型、宽度、历史与代际一起提交。被取消或失败的扫描保留上一次提交，取消操作绝不会覆盖上一次成功的结果。

### 撤销与新建扫描

撤销只提供一级，恢复上一次的数据与历史。新建扫描会清空扫描，但不会清空地址列表。

### 广域扫描的排除项

广域扫描（`begin == end == 0`）会排除本轮已知的工作缓冲区、待搜索的目标模式，以及扫描线程的栈。它不是对整个宿主的原子快照，也没有隔离所有 DLL 内存。因此并发修改、以及被释放或复用的页面都会影响结果，所得数量也无法与进程外的 CE 运行直接比较。

### 结果存储与结果列表

结果存放在文件中，不设人为的数量上限；真正的限制是磁盘空间和 64 位文件偏移。结果列表每页显示 512 行；长度超过 256 字节的值只给有限预览，只有被选中或激活时才完整读取。

## 记录、指针与写入

### 记录与冻结

- 记录带有稳定的 ID，并且可以用不同类型持有同一个地址。
- 相互冲突的重叠冻结会被拒绝。
- 冻结每 80 ms 尝试写入一次；一旦失败就自动关闭。
- 周期性冻结不是同步原语，解除冻结也不会恢复历史值。

### 指针链

指针链按 API/UI 给出的顺序逐步执行 `read_pointer(address) + signed_offset`，最多 16 级；解引用宽度由宿主的指针宽度决定。冻结每次都会重新解析整条链，因此基址搬家了也能跟上。

### 地址表达式

该求值器是 CE `symbolhandler.getAddressFromName` 的「数值/模块」子集：

- 支持多记号（token）的 `+ - *`；`*` 优先结合，而 `+`/`-` 严格从左到右求值；`--` 按 `+` 处理。
- 所有字面量都是十六进制（可选带 `0x` 或 `$` 前缀）。名称先按十六进制试，再按已加载的模块名试；名称中含有 `+`、`-` 或空格时必须加引号，例如 `"name.exe"+10`。
- 每一次加、减、乘都做溢出检查，且结果必须落在宿主的用户态地址空间内。
- 不支持符号、`[...]` 解引用、`(TYPE)` 强制转换、括号和除法，所以它仍然不是一个符号引擎。指针路径改用独立的指针扫描器获得。
- 旧的那套「在最后一个 `+`/`-` 处切分」的行为已经去掉：像 `"mod"+10-8` 这样的多记号表达式现在能正常解析了。

### 写入宿主内存

写入只触及普通的可写内存；绝不绕过保护属性，多字节写入也不保证原子性。

## 内存预览（十六进制视图）

### 显示模式与版面几何

内存页的显示类型下拉框有十种模式：字节、2、4、8 字节的十六进制与十进制，外加 Float 和 Double。单元格宽度与 ASCII 列的位置随模式变化。

| 模式 | 每单元格字节数 | 单元格宽 | 每行单元格数 | ASCII 列 | 行宽 |
|---|---|---|---|---|---|
| 字节（十六进制） | 1 | 3 | 16 | 69 | 85 |
| 字节（十进制） | 1 | 5 | 16 | 101 | 117 |
| 2 字节（十六进制/十进制） | 2 | 5 / 7 | 8 | 61 / 77 | 77 / 93 |
| 4 字节（十六进制/十进制） | 4 | 9 / 12 | 4 | 57 / 69 | 73 / 85 |
| 8 字节（十六进制/十进制） | 8 | 17 / 21 | 2 | 55 / 63 | 71 / 79 |
| Float | 4 | 16 | 4 | 85 | 101 |
| Double | 8 | 25 | 2 | 71 | 87 |

字节-十六进制模式保持其原有格式：行宽 85、ASCII 列 69。

一页为 256 字节。不可读的单元格会被标记出来且不能编辑，而这个预览也不是反汇编器。

### 十六进制单元格是按地址顺序排列的字节

一个十六进制单元格是按地址顺序排列的字节序列，而不是一个数：往 4 字节单元格里键入 `12345678`，内存中留下的是 `12 34 56 78`；若把它当作整数解析、再按小端序存储，留下的会是 `78 56 34 12`。因此十六进制单元格通过 `CE_WriteBytesV2` 写原始字节；只有十进制和浮点单元格才解析字面量，走 `CE_WriteValueV2`。

版面映射与值的格式化在 `web/js/hexview.js`；网格渲染与输入在 `web/js/memory.js`。

### 暂存与提交

- 十六进制单元格的各位数字先进入暂存缓冲区，累积到 2N 位后才写入。**暂存的内容会画在单元格里。** 这是一处修正：过去只键入一半的数字是不可见的，而且由于每次按键都会重新读取内存，单元格的第一个数字实际上被丢掉了。
- 十进制和浮点单元格宽度可变，改为按 Enter 提交、按 Escape 取消；未提交的字面量既不会写入，也不会以格式化值的形式显示出来。
- 不可读的单元格——只要其中任何一个字节读取失败——就不能编辑，在字节模式下是逐字节判定的。这纠正了早先的行为：一个 `??` 就让整行的 16 个字节都无法编辑。
- 写入失败不会改变页面上的文本。

### 光标

光标可以用点击放置，也可以用键盘移动并直接键入，无需先点一下。翻页、切换显示类型以及重新解析（Resolve）都会清空光标，因此一次编辑绝不会跑到新页面的同一偏移上继续。

### 撤销

- 每一次成功的写入（十六进制单元格、填充）都会记录 `{address, width, 之前的字节, 之后的字节}`。
- 最多保留 256 条，最旧的先被丢弃；按钮或 Ctrl+Z 恢复最新的一条。
- 这期间宿主可能已经改过那些字节。本实现会**先比较，然后照样恢复**，并在状态栏说明宿主改动过那些字节——因为拒绝撤销会让它看起来像是坏了。
- 恢复通过 `CE_WriteBytesV2` 完成（原始字节，不做解析）。
- 导航不会清空撤销栈。

### 填充

在网格上拖选一段字节范围（或用 Shift+点击扩展选区）会按字节解释填充值，并用一次 `CE_WriteBytesV2` 写入，只记为**一条**撤销条目。空选区会被拒绝，而不是被悄悄忽略；整个范围都必须是可读的：一个无法撤销的填充，比直接拒绝更糟。

### 页面历史

后退/前进在访问过的页面之间移动。一条历史记录存的是 `{已解析基址, 页面地址}`——标签显示「Resolved base」；如果只存页面，跳回去时就会显示新表达式的基址。与当前页面相同的条目会被去重。两个按钮都不会改写地址与偏移输入框（与 256 字节翻页遵循同一约定）。这是**页面**历史，不是 CE 地址栏下拉框里的表达式历史。

### 未提供

没有查找/替换，也没有按字节着色。鼠标可以拖出一段字节范围用于填充，但点击不会落在某个具体的半字节（nibble，**4 位，即一个十六进制数字**）上（Web 版本改用整单元格光标）。

## 作弊表（CT）

### V2（类型化）表

V2 会保存和加载扩展类型。它支持已实现的 CE v45 记录字段，保留 ID 与描述，覆盖数值和字节数组。字符串要求显式给出 `Length`/`Unicode`/`CodePage`；`CodePage=1` 会被拒绝，`ZeroTerminate=1` 也会被拒绝，导出时写出 `ZeroTerminate=0`。

### 字段规则

编码以原始实现为准：

- `MemoryRecordUnit.pas` 给字符串 `Length` 的容量是 `Unicode ? Length*2 : Length`；UTF-8 走 Unicode 0 / CodePage 0 作为原始字节，UTF-16 的 Length 计的是码元；ByteArray 的 `ByteLength` 单位是字节。
- CE 的 XML 存储 Offsets 时是由叶到根，执行时再反过来，所以本项目的顺序与 API 的执行顺序相反。
- 缺失 `ShowAsSigned` 时，CE 会继承一个全局设置；本实现默认为有符号，并且在被显式编辑之前一直保留「未给出」这一状态，而显式写出的 0/1 会被尊重。

导入绝不写入或冻结。只有在每个字段都校验通过之后，记录列表才会被替换，并且会检测记录修订（revision）冲突。

### 保留外来内容

本实现不认识的内容不再导致整张表被拒：它们会被保留，并在导出时原样写回。

- `<CheatEntry>` 内无法识别的子元素（`AssemblerScript`、`GroupHeader`、`Hotkeys`、`Options`、`LastState` 等）按文档顺序保留；`<CheatEntries>` 的顶层兄弟元素（`UserdefinedSymbols`、`Structures`、`Forms`、`LuaScript` 等）同样保留。
- 当 `<VariableType>` 缺失、或超出本实现能表示的范围（`Auto Assembler Script`、`Pointer`、`Grouped`、`Binary`、自定义类型）时，整条记录会作为**不透明记录**导入：地址列表显示 `CT opaque (not representable)`，数值列显示不透明提示，任何写入/冻结/编辑都返回 `CE_UNSUPPORTED`——但它可以被删除，导出时也会原样写回。判定标记是 `(last_status == CE_UNSUPPORTED && byte_length == 0)` 这个组合；正常记录不可能宽度为 0，因此这个组合不会产生歧义。
- 在同一 8 MiB 的表限制之内，保留内容每个节点上限为 4 MiB。超过上限是显式失败，绝不会被截断。

### 重新序列化

导出是**语义等价，而非字节一致**：属性顺序被排序，空元素写为 `<X></X>` 或 `<X />`，结构缩进重新排版，源文件中的注释/CDATA 不被保留（含注释的 CT 仍会被整体拒绝）。被保留的子树内部的文本原样写出（包括换行和 `&`/`<`/`>` 转义），所以脚本体永远不会被重新缩进或重新折行。

### V1 表

V1 路径（`CE_SaveTable`/`CE_LoadTable`）享受不到上述任何一条，仍然是严格的 32 位有符号子集：脚本、偏移、结构体或任何未知字段都会导致整张表被拒。

### 限制

每个文件 8 MiB，10000 条记录，描述 4096 个字符。这些是表的限制，不是扫描结果数量的限制。究竟哪些字段可接受，由源码和测试定义；并不声称任意旧的 CT 文件都普遍兼容。

## 进程视图

`CE_GetRegionsV2` / `CE_GetModulesV2` / `CE_GetThreadsV2` 每次调用各返回一个一致的快照——没有代际、缓存或刷新握手。这些快照是只读的；唯一一条改动宿主状态的命令是 `CE_UnloadModuleV2`，写在本节末尾。

| 规则 | 细节 |
|---|---|
| 计数 | `capacity`/`required` 计的是**元素**数，不是字节数；`(nullptr, 0)` 是合法的大小查询，返回 `CE_OK`。 |
| 参数错误 | `(!items && capacity)` 或 `required` 为空指针，返回 `CE_INVALID_ARGUMENT`。 |
| 缓冲区不足 | **什么都不写**，返回 `CE_INVALID_ARGUMENT`，但仍会把 `required` 设为真实数量。 |
| 硬上限 | 超过 `CE_V2_MAX_VIEW_ITEMS`（1048576）个元素返回 `CE_UNSUPPORTED`。 |
| `size`/`version` | **仅作输出**：实现会把它们写进每一个被填充的元素，所以调用方从不预先填充——与 `CeScanRequestV2` 这类输入结构体恰好相反。 |

`src/bridge/ui_bridge.cpp` 用 `static_assert` 把 48/552/168 字节的布局钉死，`runtime_v2_tests` 则在运行时断言它们。

**卸载**

`CE_UnloadModuleV2(uint64_t base)` 释放宿主进程中的一个模块，用模块枚举报出的 `base` 来指名。它是同步的，没有代际：调用方事后重新枚举。

| 规则 | 细节 |
|---|---|
| 身份 | base 必须是一个已加载模块的起始地址。`GetModuleHandleExW(GET_MODULE_HANDLE_EX_FLAG_FROM_ADDRESS, ...)` 在加载器介入之前就回答这个问题；`0` 或指向模块内部的地址返回 `CE_INVALID_ARGUMENT`。 |
| 拒绝 | 宿主 exe 与本 DLL 返回 `CE_UNSUPPORTED`。其余都会走到 `FreeLibrary`，它也可能反过来拒绝。 |
| 风险 | 模块可能正在被使用。`FreeLibrary` 可能把另一个线程正在跑的代码解除映射，宿主进程可能就此消失。没有撤销，除了上面两条拒绝之外也没有别的保护。 |
| 效果 | 只动引用计数。加载了两次的模块需要释放两次；系统或其他组件持有的模块仍然保持映射。 |

**区域**

- 按地址排序，并**平铺**覆盖从 `lpMinimumApplicationAddress` 到 `lpMaximumApplicationAddress` 的整个用户态范围，**包括 MEM_FREE / MEM_RESERVE**（CE 的 State 列也是这样做的）。因此一行 `MEM_FREE` 的 `type` 和 `allocation_protect` 都等于 0，而 `protect` 保持为 `VirtualQuery` 对空闲页面所报告的 `PAGE_NOACCESS`。
- 典型的小进程有 300–500 行；繁重的宿主可以达到几万行。遍历对每个区域做一次 `VirtualQuery`，所以刷新由用户触发，绝不轮询。

**模块与线程**

- 模块的 `path` 是内联的固定 260 个 wchar 的副本，超过 `MAX_PATH` 会被截断；线程的 `description` 固定为 64，截断方式相同。
- `CeThreadInfoV2.valid_mask`：bit0 = `description` 里存有名称，bit1 = `priority` 有效，bit2 = `created` 有效。**清零的位意味着该字段为零、不携带任何信息**——没有 `THREAD_PRIORITY_ERROR_RETURN` 之类的 Win32 哨兵值。`priority` 把 `GetThreadPriority` 的 -15..15 有符号值原样放进 `uint32_t`，`created` 是原始 FILETIME（自 1601-01-01 UTC 起的 100 ns 单位），不做隐式时区换算。
- **只读由访问掩码强制保证**：线程枚举只用 `THREAD_QUERY_LIMITED_INFORMATION` 打开线程，所以这段代码即使出意外也无法挂起、恢复或终止线程。内存保护属性、线程优先级和模块列表从不被修改。

**调用位置限制。** 模块与线程枚举使用 `CreateToolhelp32Snapshot`。该系列函数有文档记载的限制，针对的是快照「非当前进程」，而这里的宿主**就是**当前进程，所以唯一真正的风险是在调用线程持有加载器锁时调用它们（来自 `DllMain` 或堆回调）。API 调用方不得在这些位置调用它们。DLL 自己的 `DllMain` 只创建一个线程，不碰这些接口中的任何一个。

## 指针扫描

从目标地址反向查找多级指针路径；找到的结果可以作为指针记录加入地址列表。它沿用 CE 的 `pointerscancontroller.pas` + `pointerscanworker.pas`，但只做一次搜索，不做结果重扫。

### 偏移顺序

`CeAddressV2` 逐级按 `v = read(v) + offset` 解析。反向搜索时，某个槽位的值是 `当前地址 - offset`，而该槽位的地址成为下一个当前地址。因此偏移是**最先发现最内层**的，在上报之前再倒转为执行顺序。倒转后的数组照样能解析——只是会落到别的地方，这正是测试断言偏移数组的内容与顺序、而不是只断言「它能解析」的原因。

### 成本模型与上限

- 每个节点的偏移数量是 `2*max_offset/alignment + 1`；若对每个偏移各做一次二分查找，在 UI 默认值下（最大偏移 `0x1000`、对齐 8）每个节点要 1025 次查找，对齐 4 则要 2049 次——也就是 2–4 ms，与命中数量无关。
- 改为把采集到的表按值排序一次，每个节点只做**一次** `upper_bound`，然后沿着命中项向后走一遍；偏移由 `父值 - 槽位值` 自然得到。上限管的是内存；真正管住时间的是这一条。

四道闸门，且都被如实上报：

| 上限 | 取值 | 行为 |
|---|---|---|
| 采集槽位 | 4M | 返回 `CE_UNSUPPORTED`；表会预先一次性预留整整 4M 个槽位的预算，因此不可能长过这个数 |
| 每节点命中数 | 16 | 置 `truncated`，仍然返回已找到的结果 |
| 每层节点数 | 200000 | 置 `truncated`，仍然返回已找到的结果 |
| 结果数 | 65536 | 置 `truncated`，仍然返回已找到的结果 |

后三项会置上 `truncated` 位，并**仍然返回已经找到的结果**——在它刚开始有用的那一刻就整体失败，是一桩赔本买卖。UI 总是启用 `CE_PTRSCAN_NO_LOOP`（自引用的路径只会产生垃圾链）。

### 静态过滤

静态过滤的含义是「碰到一个就输出并停下」，而不是「只保留第 N 级」。地址落在某个已加载模块内的节点会立即被输出，且不再向下深入，因此一次 `levels=4` 的扫描会把它沿途找到的 2 级、3 级链一并返回。中间跳点不必是静态的；只有最外层地址会被测试。

### 验证

结果在列出之前会逐条重新解析：采集中并非原子快照，所以一条路径在被上报时可能已经悬空。每个候选都会用 `typed::resolve` 再解析一次，只有精确落在目标上才会被保留。65536 个候选 × 至多 8 次解引用，耗时以毫秒计，这就把「尽力而为」变成了一个硬性后置条件。扫描期间冻结仍在运行，所以被冻结的值会变动——这是预期内的，同样由这次重新解析覆盖。

### 与数值扫描的关系

同一时刻只运行一个任务（共享的准入与取消纪元；一次 Cancel 就能命中正在运行的那个）。除此之外两者相互独立：各自的状态结构、代际与结果集。指针扫描有自己的 `pointer` 区块和小写的阶段词汇（`enumerating` / `reading` / `walking` / ...），所以它的阶段绝不会在扫描页上被当成数值扫描的阶段渲染出来。

### 内存

每个采集槽位占 16 字节，`static` 标志放在地址的高位里（用户态地址始终低于 2^47）；四百万个槽位即 64 MiB。表按上限一次性预留，所以扩容重新分配绝不会让自排除范围失效。

### 仍然缺失

结果重扫/表复用、堆块过滤（CE 的 `useheapdata`），以及把采集表溢写到临时文件以突破 64 MiB 上限。
